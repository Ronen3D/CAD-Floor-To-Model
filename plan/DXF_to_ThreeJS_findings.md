# DXF → Three.js --- ממצאים והמלצות להמשך

## מטרת הפרויקט

המטרה היא לקחת תוכנית אדריכלית בפורמט CAD, ובשלב הראשון לעבוד מול קובץ
DXF, כדי להציג אותה כמודל 3D סכמטי ב־WebGL / Three.js.

הדיוק הגיאומטרי אינו המטרה המרכזית. הדרישה החשובה היא **שמירה על מבנה
החדרים, הקירות והיחסים המרחביים ביניהם**.

אין צורך בשלב זה לייצר GLB. הכיוון המועדף הוא:

``` text
DXF
 ↓
DXF Parser
 ↓
Geometry Extraction
 ↓
Three.js BufferGeometry
 ↓
THREE.Mesh
 ↓
WebGL
```

------------------------------------------------------------------------

# 1. הקובץ שנבדק

קובץ המקור:

`HAD-SC-P-100-002.dxf`

הקובץ נוצר מתוך תוכנית DWG שהועלתה קודם לכן:

`HAD-SC-P-100-002(1).dwg`

ה־DWG זוהה כקובץ AutoCAD 2018 (`AC1021`).

לצורך פיתוח ה־prototype, ה־DXF הוא נקודת התחלה טובה יותר משום שניתן
לקרוא ולנתח אותו ללא תלות ב־DWG SDK מסחרי.

------------------------------------------------------------------------

# 2. מבנה ה־DXF שנמצא

הקובץ מכיל בעיקר ישויות 2D.

ספירה שנמצאה:

  Entity                כמות משוערת
  ------------------- -------------
  `LINE`                      2,171
  `INSERT` / Blocks             554
  `DIMENSION`                   284
  `HATCH`                       180
  `MTEXT`                       165
  `TEXT`                        116
  `LWPOLYLINE`                    4
  `CIRCLE`                        2
  `ELLIPSE`                       6

הממצא החשוב ביותר הוא שהשרטוט מחולק לשכבות בעלות משמעות אדריכלית ברורה.

------------------------------------------------------------------------

# 3. שכבות חשובות

שכבות מרכזיות שנמצאו:

-   `A-WALL` --- קירות
-   `I-WALL` --- קירות פנימיים
-   `A-DOOR` --- דלתות
-   `A-GLAZ` --- זכוכית / חלונות
-   `A-FLOR` --- רצפות
-   `S-COLS` --- עמודים
-   `I-FURN` --- ריהוט
-   `P-SANR-FIXT` --- כלים סניטריים
-   `S-STRS` --- מדרגות

לכן אין צורך לנסות להבין את כל ה־DXF בבת אחת.

אפשר להשתמש ב־Layer כ־semantic information.

לדוגמה:

``` js
if (entity.layer === "A-WALL" ||
    entity.layer === "I-WALL") {
    // wall geometry
}
```

------------------------------------------------------------------------

# 4. מסקנה מרכזית

הקובץ מתאים מאוד לגישה של:

**DXF → Geometry → Three.js**

ולא בהכרח:

**DXF → CAD 3D → GLB → Three.js**

מכיוון שהשרטוט הוא בעיקר תוכנית 2D, ניתן ליצור ממנו מודל 3D פשוט באמצעות
extrusion.

לדוגמה:

``` text
2D wall geometry
      ↓
detect wall segment
      ↓
determine thickness
      ↓
extrude to wall height
      ↓
THREE.BufferGeometry
      ↓
THREE.Mesh
```

------------------------------------------------------------------------

# 5. הצעת Architecture

מומלץ להפריד את הפרויקט לשלוש שכבות:

## A. DXF Parser

אחראי רק על קריאת ה־DXF והפיכת ה־entities לנתונים נוחים לעבודה.

לדוגמה:

``` js
{
  type: "LINE",
  layer: "I-WALL",
  start: [x1, y1],
  end: [x2, y2]
}
```

ה־parser לא צריך לדעת דבר על Three.js.

------------------------------------------------------------------------

## B. CAD → Architectural Geometry

שכבה זו מפרשת את הנתונים:

-   אילו entities הם קירות
-   אילו הם דלתות
-   אילו הם חלונות
-   אילו הם רצפות
-   אילו הם מדרגות
-   אילו entities אפשר להתעלם מהם

הפלט יכול להיות מודל פנימי פשוט:

``` js
{
  walls: [...],
  doors: [...],
  windows: [...],
  floors: [...],
  columns: [...],
  stairs: [...]
}
```

------------------------------------------------------------------------

## C. Three.js Renderer

רק כאן נכנס Three.js.

לדוגמה:

``` js
const geometry = new THREE.BufferGeometry();

geometry.setAttribute(
  "position",
  new THREE.BufferAttribute(vertices, 3)
);

geometry.setIndex(indices);
geometry.computeVertexNormals();

const mesh = new THREE.Mesh(
  geometry,
  wallMaterial
);

scene.add(mesh);
```

כך אפשר להחליף בעתיד את ה־DXF parser ב־DWG/WASM parser בלי לשנות את שכבת
ה־Three.js.

------------------------------------------------------------------------

# 6. Prototype ראשון מומלץ

לא לנסות לתמוך בכל סוגי ה־CAD.

ה־MVP צריך להתמקד רק ב:

### Phase 1

**קירות + רצפות**

``` text
DXF
 ↓
A-WALL / I-WALL
 ↓
Wall segments
 ↓
3D extrusion
 ↓
Three.js
```

גובה קיר יכול להיות ערך קבוע, למשל:

``` js
const WALL_HEIGHT = 2800;
```

אין צורך בשלב הראשון להסיק את הגובה מה־CAD.

------------------------------------------------------------------------

# 7. בעיה שצריך לפתור: עובי קירות

ב־DXF הקירות עשויים להופיע כ:

1.  שני קווי `LINE` מקבילים
2.  Polyline
3.  מספר segments שמרכיבים קיר
4.  שילוב של קווים ו־Blocks

לכן לא כדאי להניח שכל `LINE` הוא קיר תלת־ממדי בפני עצמו.

צריך קודם לבדוק את הגיאומטריה בפועל.

### אפשרות פשוטה

אם קיימים שני קווים מקבילים במרחק קטן:

``` text
LINE ───────────────────
LINE ───────────────────
```

להתייחס אליהם כאל שני הצדדים של אותו קיר.

### אפשרות פשוטה יותר ל־MVP

להפוך כל segment ל־rect בעל thickness קבוע:

``` text
          wall thickness
       <---------------->
       ┌─────────────────┐
       │                 │
       └─────────────────┘
       <------ line ----->
```

זה כנראה מספיק לתוצאה הסכמטית הרצויה.

------------------------------------------------------------------------

# 8. דלתות

שכבת `A-DOOR` קיימת, ולכן כדאי לטפל בדלתות בנפרד.

בשלב הראשון אפשר להציג אותן כאובייקטים פשוטים:

``` text
wall
───────────────┐ ┌────────
               │ │
               │ │ door
───────────────┘ └────────
```

אין צורך במודל דלת מפורט.

אפשר גם להשתמש ב־Block definitions מתוך `INSERT`, אם יתברר שה־Blocks
מכילים מידע שימושי.

------------------------------------------------------------------------

# 9. חדרים

זו נקודה חשובה במיוחד לפרויקט.

המטרה הסופית היא לא רק לראות קירות, אלא להיות מסוגלים לזהות חדרים:

``` js
room.userData = {
    id: "ROOM_101",
    name: "Conference Room"
};
```

לכן כדאי לבנות בשלב מאוחר יותר אלגוריתם שמזהה **closed regions** מתוך
הקירות.

לדוגמה:

``` text
┌───────────────┐
│               │
│    ROOM A     │
│               │
├───────────────┤
│               │
│    ROOM B     │
│               │
└───────────────┘
```

כל region סגור יהפוך ל־room polygon.

זה יאפשר בהמשך:

-   בחירת חדר
-   הדגשת חדר
-   הצגת שם
-   הצגת שטח
-   צבע לפי קטגוריה
-   navigation
-   חישוב מסלולים

# 11. Coordinate System

צריך לזכור ש־CAD משתמש במערכת צירים שונה מהדרך שבה נוח להציג מודל
ב־Three.js.

מומלץ להגדיר טרנספורמציה אחת ברורה:

``` text
CAD:
X → X
Y → Z
Z → Y
```

או פשוט לעבוד עם:

``` js
threeX = cadX;
threeY = height;
threeZ = -cadY;
```

כך:

-   CAD X → Three X
-   CAD Y → Three Z
-   גובה → Three Y

מומלץ לבצע את הטרנספורמציה במקום אחד בלבד בקוד.

------------------------------------------------------------------------

# 12. Units / Scale

לפני בניית המודל יש לזהות את יחידות השרטוט.

אם היחידות הן millimeters:

``` js
const SCALE = 0.001;
```

כך:

``` text
1000 CAD units
      ↓
1 meter
```

חשוב לבצע בדיקת sanity:

-   דלת ≈ 800--1000 mm
-   קיר ≈ 100--300 mm
-   חדר ≈ כמה מטרים

אם המספרים הגיוניים, ה־scale כנראה נכון.

------------------------------------------------------------------------

# 13. Performance

אין צורך ליצור Mesh נפרד לכל `LINE`.

עדיף לבצע batching:

``` text
all walls
   ↓
one BufferGeometry
   ↓
one THREE.Mesh
```

או מספר קטן של Meshes לפי category:

``` text
Walls
Floors
Doors
Windows
Columns
```

זה יפחית draw calls ויהיה יעיל יותר ב־WebGL.

# 17. DWG בעתיד

בשלב הראשון **לא כדאי להתחיל מ־DWG ישירות**.

ה־DXF מספק סביבת פיתוח פשוטה יותר.

אחרי שהאלגוריתם עובד:

``` text
DXF
 ↓
Architectural Geometry
 ↓
Three.js
```

אפשר להחליף את המקור:

``` text
DWG
 ↓
DWG Parser / WASM
 ↓
Architectural Geometry
 ↓
Three.js
```

כך כל הלוגיקה של יצירת המודל נשארת זהה.

אפשר לשקול בעתיד:

-   ODA SDK
-   LibreDWG / WebAssembly
-   parser אחר שתומך ב־DWG

אין צורך לקבל החלטה זו בשלב ה־MVP.

# 18. המלצה מסכמת

הכיוון המומלץ לפרויקט:

**לא להמיר את ה־DXF ל־GLB.**

במקום זאת:

``` text
              DXF
               │
               ▼
          DXF Parser
               │
               ▼
      Architectural Model
               │
       ┌───────┼────────┐
       ▼       ▼        ▼
     Walls   Floors    Doors
       │       │        │
       └───────┼────────┘
               ▼
        Three.js Geometry
               │
               ▼
          THREE.Mesh
               │
               ▼
             WebGL
```

הקובץ שנבדק כבר מכיל שכבות סמנטיות כמו `A-WALL`, `I-WALL`, `A-DOOR`,
`A-GLAZ`, `A-FLOR` וכו', ולכן יש בסיס טוב מאוד לבניית converter ממוקד
ולא parser CAD כללי.

**היעד הראשון צריך להיות פשוט:** לקחת את `A-WALL` ו־`I-WALL`, ליצור מהם
קירות תלת־ממדיים, להוסיף רצפה, ולהציג אותם ב־Three.js. רק לאחר שהשלד הזה
עובד כדאי להוסיף דלתות, חלונות וזיהוי חדרים.
